快速上手

  1. 点击浏览器工具栏图标打开弹窗。
  2. 点击「+ 新增规则」，填写请求头名称(key)和值(value)。规则固定使用 set：已有同名请求头时覆盖，否则新增。
  3. 可选填写 URL 匹配，留空则对所有请求生效。
  4. 改动即时保存并生效，无需手动确认。

示例：给所有发往 api.example.com 的请求设置认证头 —— key 填 Authorization，value 填 Bearer xxx，URL 匹配填 *://api.example.com/*。

规则字段说明

字段说明
启用开关每条规则独立的开关，关闭后该规则立即失效但配置保留。
名称(key)要修改的头名称，如 X-Custom-Header。启用状态下留空会显示红框，该规则不会生效。
值(value)写入请求头的内容。同名请求头已存在时覆盖，否则新增。
URL 匹配限定规则生效的地址，支持通配符（* 匹配任意字符），如 *://api.example.com/* 只匹配该域名本身、*://*.example.com/* 匹配 example.com 及其子域。端口无需写出，*://api.example.com/* 同样匹配 api.example.com:8080；要限定端口就显式写成 *://localhost:8080/*。不含 :// 的写法按子串匹配整个地址，如 api.example.com、/api/v1。留空匹配所有请求。

总开关与角标

弹窗和管理页右上角的总开关可一键暂停 / 恢复所有规则，暂停时配置不会丢失。

工具栏图标角标反映当前状态：

  • 数字（蓝色）：当前生效的规则数量。
  • OFF（灰色）：总开关已关闭。
  • ERR（红色）：规则同步失败，打开弹窗或管理页可看到具体错误原因。

配置档

配置档（Profile）是一组独立的规则集合，适合按场景组织，例如「开发环境」「测试环境」各存一套请求头。

  • 同一时间只有一个配置档生效（弹窗顶部下拉框或管理页单选按钮切换）。
  • 管理页可新增、重命名、删除配置档；最后一个配置档不可删除。
  • 切换配置档后规则立即按新配置档生效。

管理页

点击弹窗中的「管理」按钮进入完整管理页，适合规则较多时使用：

  • 搜索：按 key / value / URL 关键字过滤规则。
  • 排序：每行的 ↑ / ↓ 按钮调整规则顺序。
  • 批量操作：勾选多条规则后一键启用、停用或删除；「全选」作用于当前搜索结果。
  • 规则区与配置档区联动：列表展示并编辑的始终是「当前启用」的配置档（标题旁有标签指示），在配置档区切换启用后，规则列表会同步跟随。
  • 弹窗和管理页右上角均可切换界面语言（English / 中文）。初始语言按浏览器语言自动判断：中国大陆 / 香港 / 澳门 / 台湾默认中文，其他默认英文；手动切换后以所选为准，对弹窗、管理页和本帮助页统一生效。

导入 / 导出

  • 导出 JSON：把全部配置档与规则保存为一个 JSON 文件，可用于备份或分享给同事。
  • 导入 JSON：读取导出的文件并覆盖当前全部配置（导入前会弹窗确认）。格式不正确的文件会被拒绝，规则字段会逐条校验清洗。

常见问题

规则填好了但没生效？

  • 检查角标是不是 OFF（总开关关闭）或 ERR（同步失败，弹窗内有错误原因）。
  • 确认当前生效的配置档是不是规则所在的那个。
  • URL 匹配写法是否正确，可先留空试试是否全局生效。
  • 部分受浏览器保护的头（如 Host）无法修改。
  • 用 DevTools 的 Network 面板选中该请求，在 Headers 里核对头是否已被改写。

Firefox 有什么差异？需要 Firefox 128 及以上；临时载入的插件重启后会消失。

Quick start

  1. Click the toolbar icon to open the popup.
  2. Click "+ Add rule", then fill in the request header name (key) and value. Rules always use set: an existing header is overwritten, otherwise it is added.
  3. Optionally add a URL filter; leave it empty to match all requests.
  4. Changes are saved and applied immediately.

Example: set an auth header on every request to api.example.com — key Authorization, value Bearer xxx, URL filter *://api.example.com/*.

Rule fields

FieldDescription
Enable switchPer-rule switch. Turning it off deactivates the rule immediately while keeping its configuration.
Name (key)The header to modify, e.g. X-Custom-Header. An enabled rule with an empty key shows a red border and has no effect.
ValueContent written to the request header. An existing header is overwritten; otherwise it is added.
URL filterLimits where the rule applies. Wildcards supported (* matches anything): *://api.example.com/* matches that host only, *://*.example.com/* matches example.com and its subdomains. Ports need not be written out — *://api.example.com/* also matches api.example.com:8080; write *://localhost:8080/* to pin a port. A value without :// is matched as a substring of the whole URL, e.g. api.example.com, /api/v1. Empty matches all requests.

Master switch & badge

The switch at the top-right of the popup and the manager page pauses / resumes all rules at once without losing any configuration.

The toolbar badge reflects the current state:

  • Number (blue): count of rules currently in effect.
  • OFF (gray): the master switch is off.
  • ERR (red): rule sync failed; open the popup or manager page to see the error.

Profiles

A profile is an independent set of rules, useful for organizing by scenario — e.g. one profile for "Dev" and another for "Staging".

  • Only one profile is active at a time (switch via the popup dropdown or the radio buttons on the manager page).
  • Profiles can be added, renamed, and deleted on the manager page; the last remaining profile cannot be deleted.
  • Switching profiles takes effect immediately.

Manager page

Click "Manage" in the popup to open the full manager page, handy when you have many rules:

  • Search: filter rules by key / value / URL keywords.
  • Sorting: reorder rules with the ↑ / ↓ buttons on each row.
  • Batch actions: select multiple rules to enable, disable, or delete them at once; "Select all" applies to the current search results.
  • The rules section is linked to the profiles section: it always shows and edits the active profile (indicated by the tag next to the title), and follows along when you switch profiles.
  • The selector at the top-right of both the popup and the manager page switches the interface language (English / 中文). The initial language follows your browser locale — Chinese for mainland China, Hong Kong, Macao, and Taiwan, English elsewhere; once switched manually, your choice applies to the popup, the manager page, and this help page.

Import / Export

  • Export JSON: saves all profiles and rules to a JSON file for backup or sharing.
  • Import JSON: reads an exported file and replaces the current configuration (with a confirmation prompt). Invalid files are rejected and every rule is validated and sanitized.

FAQ

My rule doesn't work?

  • Check the badge: OFF means the master switch is off; ERR means sync failed (the popup shows the error).
  • Make sure the active profile is the one containing your rule.
  • Verify the URL filter; try leaving it empty to test globally first.
  • Some browser-protected headers (e.g. Host) cannot be modified.
  • Select the request in the DevTools Network panel and check its Headers to see whether the header was rewritten.

Firefox differences? Requires Firefox 128+; temporarily loaded add-ons disappear after a restart.
